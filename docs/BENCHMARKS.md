# Benchmark notes

`benchmark-results.csv` contains a local run from `./build/vtlc_bench`: three repetitions, median wall-clock time, 16 frames of 16,384 elements (1 MiB), deterministic synthetic data. Each codec includes output and scratch allocations. Bitwise validation occurs after timing. VTLC includes container metadata and CRC; bare Zstandard baselines do not. Raw storage ratio is 1.0. Ratios are compressed bytes divided by original bytes; reduction is `1-ratio`. Each repetition runs in a separate forked subprocess, with its peak RSS reported by `wait4`; the table shows the median peak. It includes the input and inherited process footprint, not only codec allocations, and measures the combined encode/decode run.

`kernel-results.csv` measures repeated prediction-only operations on fixed arrays, in input MiB/s; arrays are cache-resident and the measurement is not end-to-end codec throughput. The scalar baseline can be auto-vectorized by the compiler. Kernel results have not been measured on AVX-512 hardware.

Synthetic distributions and RNG seed are defined in `benchmarks/benchmark.cpp`; they do not represent all real datasets or systems and do not imply a 30–50% guarantee. Results cover Zstandard levels 1 and 3, bitshuffle+Zstandard, temporal XOR+Zstandard, and several VTLC configurations. They omit real datasets, per-operation peak memory, independently started processes, and broad third-party codec comparisons. Rerun locally rather than extrapolate. The recorded machine is an AMD Ryzen 7 5800X running x86-64 Linux with GCC 16.2.1 and Zstandard 1.5.7.
